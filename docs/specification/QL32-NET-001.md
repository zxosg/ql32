# QL/32 — Network Service Contract

**Document ID:** QL32-NET-001  
**Status (2026-11-01):** M6 Wi-Fi station service and ESP32 adapters implemented.
CYD hardware acceptance passed for association, status, address, signal, and
disconnect; VGA32 physical acceptance remains pending.

## Scope

The first M6 network slice supports a Wi-Fi station connection. Joining and
leaving a network are asynchronous service operations. The BASIC VM never waits
for association; programs can inspect the current state on later statements.
Access points, HTTP, sockets, BLE, credential persistence, and background
reconnection policy are outside this slice.

`ql32::runtime::NetworkService` defines `connectWifi`, `disconnectWifi`, and
`wifiStatus`. A status contains one of `Disconnected`, `Connecting`, `Connected`,
or `Failed`, plus an IPv4 address and signal level when connected. The ESP32
adapter uses station mode. Disconnect clears the Wi-Fi driver's remembered
AP configuration. Credentials are not written by QL/32 to storage.

## BASIC calls

| Call | Behavior |
| --- | --- |
| `GETNET ssid$, password$` | Start an asynchronous Wi-Fi station connection |
| `DISNET` | Disconnect and clear the adapter's remembered AP |
| `NETSTAT$()` | Return `DISCONNECTED`, `CONNECTING`, `CONNECTED`, or `FAILED` |
| `NETADDR$()` | Return the IPv4 address, or an empty string unless connected |
| `NETSIGNAL()` | Return signal strength in dBm, or `0` unless connected |

All calls require the board's network service. A host with no network adapter
raises the standard `Unavailable` service error. The names avoid collisions
with SuperBASIC's mandatory-letter keyword abbreviations. They are QL/32 APIs,
not SuperBASIC compatibility claims.

Wi-Fi passwords may be present in command input or source text supplied to
`GETNET`; avoid saving or sharing programs containing real credentials. The
service does not persist credentials. The board REPL echoes entered lines.

## M6 acceptance

- Linux tests cover call dispatch, asynchronous state changes, status values,
  and unavailable-service errors.
- Both ESP32 profiles compile the Wi-Fi adapter and advertise network service
  capability.
- Hardware acceptance requires joining a local access point, observing
  `CONNECTED`, reading an IPv4 address and signal strength, then disconnecting.
- The CYD hardware check passed: association reached `CONNECTED`, address and
  signal queries worked, and `DISNET` returned the state to `DISCONNECTED`.
  VGA32 still requires the same physical check when that board is available.
- For the CYD board, build and flash `esp32_2432s028`, open the 115200-baud
  serial monitor, and enter these lines at the BASIC prompt, replacing the
  placeholders locally:

  ```basic
  GETNET "YOUR_WIFI_SSID", "YOUR_WIFI_PASSWORD"
  PRINT NETSTAT$()
  ```

  Repeat the status query after a few seconds. When it reports `CONNECTED`,
  check `PRINT NETADDR$()` and `PRINT NETSIGNAL()`, then enter `DISNET` and
  confirm the state returns to `DISCONNECTED`. The serial REPL echoes input;
  do not share logs or save a program containing real credentials.
- Both ESP32 profiles use a custom 4 MiB single-app partition with 3.875 MiB
  available for firmware. Wi-Fi currently occupies about 30% of it. This
  layout has no OTA slot or internal filesystem; BASIC files use SD. Future
  OTA support would need a different partition plan or more flash.
- Future slices can add bounded HTTP or socket APIs after their data model and
  timeout behavior are specified. BLE remains a later milestone.
- Network connections exposed as ordinary BASIC channels are backlog work,
  separate from this Wi-Fi station M6 slice. Endpoint syntax, transport,
  client/server roles, buffering, timeout, EOF, and error semantics need a
  design before implementation.
