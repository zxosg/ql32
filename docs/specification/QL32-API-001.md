# QL/32 — Public API Baseline

The public API comprises language commands and portable native-service
contracts. API definitions must identify compatibility class, availability,
errors, ownership, and blocking/scheduling behavior before implementation.

## M1 source inclusion

`INCLUDE "relative/path.bas"` is a QL/32-specific compile-time source
directive. It expands a BASIC library/header from the configured storage
service before compilation; included procedures/functions join the current
module. It is limited to the source preamble, recursive depth 16, and 64 KiB of
expanded source. Module-level `CONST name = literal` declarations are available
for numeric and string literals and are immutable. The repository's
`ql32.inc` provides channel selector constants; programs include it explicitly.
See [QL32-LANG-001](QL32-LANG-001.md#22-source-inclusion) for path, cycle,
constant placement, and diagnostic behavior.

## M2 host command slice

The Linux interactive command loop supports `LOAD "path"`, `SAVE "path"`, and
`DIR ["path"]` over the configured storage service. Paths are quoted, relative
to the storage root, and isolated from host absolute paths and parent traversal.
`LOAD` accepts numbered BASIC source lines, validates a candidate program before
replacing the current one, and clears session variables only after success.
`SAVE` serializes the numbered program; `DIR` lists immediate entries in sorted
name order. These are QL/32-specific command semantics pending compatibility
references.

`ql32::runtime::MemoryService` supplies `FREE()` with a platform-specific free
memory snapshot. ESP32 reports currently free 8-bit-capable heap; Linux reports
`MemAvailable` (with an available-pages fallback). Values are bytes and do not
represent memory owned by one BASIC session.

`ql32::ui::Service` defines asynchronous alert and confirmation requests keyed
by session and request IDs. `QueuedService` delivers requests to a host adapter;
results are consumed once by polling, and canceling a session removes its
outstanding requests. BASIC exposes `ALERT title$, message$` as a command
and `CONFIRM(title$, message$)` as a numeric function (`1` confirmed, `0`
cancelled). `executeResumable` returns `Suspended` while either request waits;
the host dispatches it through the service and calls `resume` when ready. VM
state is retained per interpreter, so other sessions can continue. Clearing or
destroying an interpreter cancels its outstanding UI requests. The synchronous
`execute` convenience reports an error if a BASIC program suspends and should
not be used by a host that needs to handle UI requests.

## M3 graphics slice

The portable graphics service owns one default pixel window per BASIC session.
The window is created lazily on first use. Coordinates are integer pixels with
`(0,0)` at the top-left; drawing outside the window is clipped. Ink and paper
are indices into a session's color palette, initially the QL eight-color order
(black, blue, red, magenta, green, cyan, yellow, white). The service owns
graphics state and exposes no platform drawing types. Palette edits and
cycling are deferred. The QL/32-specific command syntax is
`INK index`, `PAPER index`, `LINE x1,y1,x2,y2`,
`RECT x,y,width,height`, `CIRCLE cx,cy,radius`, `TEXT x,y,text$`,
`ROTATE degrees`, `WINDOW x,y,width,height`, and `CLS`. `WINDOW` moves and
resizes the current session's screen window; drawing coordinates remain local
to its canvas. `CLOSEWINDOW` releases the current session's graphics canvas;
the next graphics command creates a fresh default window. `RECT` and `CIRCLE`
draw outlines; `TEXT` positions the top-left of the text; `CLS` fills with the
current paper color. Coordinates, dimensions,
radii, and color indices must be integers. `INK` and `PAPER` accept values in
the active window palette. The Linux, CYD, and VGA32 4-bit windows accept
indices 0..15; VGA output maps the palette to its available hardware colors.

The portable `graphics::WindowManager` canvas API accepts `PixelDepth::One`,
`PixelDepth::Four`, and `PixelDepth::Eight`; new windows default to
`PixelDepth::Four`. Pixels are packed at 1, 4, or 8 bits, and each canvas
exposes the corresponding 2, 16, or 256 index range.
Changing depth preserves the canvas while truncating stored indices to the new
depth. `WindowManager` can enforce a total canvas-byte budget. This C++ API is
connected to the Linux, CYD, and VGA32 BASIC graphics services. `WINDOW` moves
or resizes the current session's window. The C++ supervisor methods can also
hide, raise, or tile session windows; BASIC commands for a supervisor to
control other sessions are not implemented yet.

The current pixel window can be queried with `GWIDTH()`, `GHEIGHT()`,
`GORIGINX()`, `GORIGINY()`, `GDEPTH()`, `GROTATION()`, and `GPALETTESIZE()`.
`GORIGINX()` and `GORIGINY()` return its top-left position in absolute screen
pixels. `GPALETTE$(index)` returns
the indexed color as an uppercase `#RRGGBB` string. `ROTATE degrees` requests
one of 0, 90, 180, or 270 degrees clockwise; it is supported by the CYD TFT
adapter and reports an unsupported-operation error on adapters without
rotatable displays. These QL/32-specific calls return live window dimensions
in pixels, bits per pixel, current orientation, and palette entry count.

`ql32::runtime::ChannelService` opens session-owned file channels in read,
truncate, or append mode. It provides line reads with explicit EOF, text writes,
exact-byte reads and writes, absolute seek, individual close, and session cleanup.
The Linux directory adapter confines channel paths to its configured root. The current BASIC file
form is `OPEN(path, mode)`; the unified channel design will generalize this to
`OPEN(deviceKind, parameters...)`, returning an automatically allocated numeric
channel handle. A window open will receive numeric position and size arguments
rather than geometry encoded in a device-name string. There will be no explicit
channel-number form of `OPEN`. `READ$(channel)` is a line read,
`EOF(channel)` as a non-consuming 1/0 check, `WRITE channel, text` as a
newline-terminated write, and `CLOSE channel` to release a handle. Modes are
`"READ"`, `"WRITE"` (truncate), and `"APPEND"`. At EOF, `READ$` returns an empty
string; `EOF` distinguishes that from an empty line. Handles are valid only in
the interpreter session that opened them and close when it ends. These
QL/32-specific calls are not historical channel syntax.

Line-oriented `INPUT` defaults to keyboard channel `#0`; file handles may be
selected explicitly. Prompts default to output channel `#1`. Supported forms
include `INPUT variable`, `INPUT prompt$; variable`, `INPUT #file, variable`,
`INPUT prompt$ #file, variable`, and the explicit form
`INPUT #promptChannel, "prompt", #readChannel, variable`. Keyboard input
suspends only its BASIC session; file input reads one line synchronously.
Serial input endpoints are not implemented.

Exact byte transfers and random access use `#channel IN count, buffer$`,
`#channel OUT count, buffer$`, and `#channel AT offset`. `AT` sets a zero-based
absolute position; `IN` requires the full byte count, and `OUT` writes the
requested prefix of the string as opaque bytes. Operations are limited to
8192 bytes. Linux directory files and ESP32 SD files support them. Append
channels cannot seek. Strings preserve arbitrary bytes for these operations,
but are not safe for text functions when they contain invalid UTF-8. This
replaces the earlier proposed `INPUT count, #channel, buffer$` and `SEEK`
spellings and avoids Toolkit II's combined `#channel\position` notation.

Channels are universal, session-owned handles to I/O endpoints. Reserve `#0`
for the CON-like command/error console and keyboard input, and `#1` for the
user/program output window and graphics. These IDs exist at startup; additional
channels and their resources are allocated on demand to limit memory use.
Unqualified `PRINT` and graphics commands target `#1`; command input, BASIC
`INPUT`, and system/error messages use `#0`. Generic `OPEN(deviceKind,
parameters...)` returns a channel handle; for a window, that same handle selects
the window for text and graphics. File, serial, null, and future network opens
use the same function and allocate handles in the same namespace. `#0` and `#1`
are reserved; additional handles are assigned automatically when opened.

I/O commands that support redirection accept an explicit channel selector:
`PRINT #channel,...`, `LIST #channel`, `CIRCLE #channel,...`, and corresponding
input/output commands. Endpoint type determines supported operations. `LIST
#1` draws a listing in the output window; if `#2` is opened for file writing,
`LIST #2` writes the listing to that file. `CHANNEL #channel` changes the
logical default for unqualified output operations, including graphics. An
operation selects its logical channel from an explicit selector or the current
default. `CHANNEL #source TO #destination` directly rebinds the source
handle to the endpoint currently bound to the destination. Thus `CHANNEL #1 TO
#2` rebinds `#1`; all operations using
`#1` then use that endpoint. The binding is session-local, direct, and shared
with the destination endpoint's state. The channel keeps its original endpoint
so `CHANNEL #1 TO #1` restores it. The runtime stores a one-step binding to
the destination's currently active endpoint; it does not retain route chains.
Text, graphics, line input, exact-byte I/O, seeking, and endpoint-type queries
use the active binding.
If the selected endpoint lacks a requested capability, the operation reports
an unsupported-operation error. Changing the default to `#0` makes unqualified
operations select `#0`; explicit channel selectors still select their handle
and its active binding. `GETCHANNEL(KChannelCount)` returns the
count of open channels in the current session, including reserved `#0` and
`#1`; `GETCHANNEL(KChannelHandle, position)` returns the handle at that
zero-based position in ascending-handle order; `GETCHANNEL(KChannelType,
#handle)` returns a symbolic type string such as `CONSOLE`, `WINDOW`, or `FILE`.
These selectors are named constants from `ql32.inc`. Count, handle, and type
queries are implemented for the reserved console/window channels and open file
channels. Other endpoint types will appear as their adapters are added. A null
output endpoint accepts and discards output and graphics operations without
side effects or endpoint errors; this endpoint is planned and unavailable.
Closing an open file channel releases its endpoint resources. The `CLOSE`
command closes the selected handle's original file endpoint; other logical
channels bound to that endpoint return to their own original endpoints.
`CLOSE` does not yet close or reopen reserved `#0` and `#1`; their lifecycle
is part of the unfinished endpoint registry.

The interpreter routes unqualified `PRINT`, `LIST`, and `DIR` to the current
default (initially `#1`). `PRINT`, `LIST`, `DIR`, and `WRITE` accept explicit
channel targets where applicable. `CHANNEL #channel` changes the default for
unqualified output. `CHANNEL #source TO #destination` updates the source's
active endpoint binding, as described above.
Text can target the console stream (`#0`), retained window (`#1`), or an open
file channel. Graphics commands accept explicit channel selectors and use the
same default and routing rules, but the resolved endpoint must be the graphics
window (`#1`). `READ$` and `EOF` support open file channels. BASIC `INPUT`
supports keyboard line input through the asynchronous UI broker and
synchronous line input from file handles. Serial and null input endpoints,
network endpoints, and a unified endpoint registry remain open work. File
channels additionally support exact-byte `IN`/`OUT` and absolute `AT`
positioning, as specified above.

## M4 managed UI foundation

The M4 graphics window manager owns retained canvases and portable window
properties. The startup reserves `#0` for the command/error console and `#1`
for user/program output with graphics. Additional channel IDs and window
backing are allocated on demand. Each window channel owns its text state and
retained canvas. `PRINT #channel,...` and graphics commands address a selected
window. The same namespace addresses file, serial, and future network
endpoints, subject to their capabilities. The supervisor may update a window's
position, viewport, visibility, or stacking order and request a tiled
arrangement. The compositor redraws
affected screen regions from the canvases so overlapping windows never destroy
covered content. Window management is independent of interpreter scheduling
and platform drawing libraries. See
[QL32-UI-001](QL32-UI-001.md#m4-window-manager-and-compositor).

The queued UI service accepts session-owned dialog schemas with ordered text,
edit, integer, float, choice, and check fields. A presenter submits typed values
as one result; it rejects wrong types and out-of-range numeric values. The Linux
console presenter handles all current field types and menu selection for host
testing. A cancelled dialog yields no field updates. Menus carry unique, nonzero command
IDs separately from labels and shortcut strings; selection returns the ID, not
the visual item position. These definitions and results use the asynchronous
request queue. BASIC declaration commands and VM resumption for dialog/menu
results are implemented through session-owned `DINIT`/`DIALOG` and
`MINIT`/`MENU` handles. `DGET$` and `DGET` retrieve submitted dialog values;
`MENU` returns the stable command ID or zero on cancellation. Linux console
presentation and a non-blocking ESP32 line presenter are implemented. The
embedded presenter accepts one line per prompt; board-specific visual dialog
layouts are not part of this line presenter.

## M5 clock service

`ql32::runtime::ClockService` provides optional Unix epoch seconds for wall
time and monotonic milliseconds for elapsed-time measurement. A target may
report wall time as unavailable until its clock is set or synchronized; elapsed
time remains available. The Linux adapter supplies host system and steady
clocks. No BASIC clock functions or setter API are defined yet.

## M6 Wi-Fi service

`ql32::runtime::NetworkService` starts Wi-Fi station association asynchronously
and reports `Disconnected`, `Connecting`, `Connected`, or `Failed`, with IPv4
and signal strength when connected. BASIC exposes the commands
`GETNET ssid$, password$` and `DISNET`, plus the functions `NETSTAT$()`,
`NETADDR$()`, and `NETSIGNAL()`. A missing adapter
reports `Unavailable`; see [QL32-NET-001](QL32-NET-001.md) for state and
credential-handling details. The first platform adapter is ESP32 Wi-Fi station
mode. HTTP, sockets, and BLE are later slices.
