# QL/32 — Public API Baseline

The public API comprises language commands and portable native-service
contracts. API definitions must identify compatibility class, availability,
errors, ownership, and blocking/scheduling behavior before implementation.

## M1 source inclusion

`INCLUDE "relative/path.bas"` is a QL/32-specific compile-time source
directive. It expands a BASIC library/header from the configured storage
service before compilation; included procedures/functions join the current
module. It is limited to the source preamble, recursive depth 16, and 64 KiB of
expanded source. Module-level `CONST name = literal` declarations are available
for numeric and string literals and are immutable. The repository's
`ql32.inc` provides channel selector constants; programs include it explicitly.
See [QL32-LANG-001](QL32-LANG-001.md#22-source-inclusion) for path, cycle,
constant placement, and diagnostic behavior.

Scalar strings support `LEN(string$)`, `LEFT$(string$, count)`,
`RIGHT$(string$, count)`, and `MID$(string$, start[, count])`. Indexes count
UTF-8 code points and are one-based for `MID$`. Zero length returns an empty
string, counts past the end are clipped, and a positive start after the end
returns an empty string. Negative or fractional positions/counts are invalid
arguments. `MID$` without count returns through the end. The count and
indexing conventions align with OPL where applicable; optional `MID$` length
follows Annex32, while the functions are convenience equivalents to
SuperBASIC's native string slices. No source-compatibility claim is made.

## M2 host command slice

The interactive command loop supports `LOAD "path"`, `SAVE "path"`,
`DIR [path]`, `CD path$`, `DELETE path$`, `RENAME path$,newpath$`, and
`FORMAT path$` over the configured storage service. File paths are quoted or
provided through string variables; `CD`, `DIR`, and `FORMAT` also accept bare
path text. Relative paths use the current directory owned by the interpreter
session. `.` and `..` walk directories without escaping the selected volume.
`FFS:/path` names the internal flash filesystem and
`SDC:/path` names the removable SD card; these drive names are case-insensitive
and are the canonical QL/32 volume identifiers. The root forms are `FFS:/` and
`SDC:/`. A path without a drive prefix uses the platform's default volume.
Paths are isolated from host absolute paths and parent traversal. The drive
prefix syntax is defined for all storage-path operations, including `LOAD`,
`SAVE`, `DIR`, `INCLUDE`, `TASK`, and file channels. Current platform startup
still installs one storage backend per firmware image; dispatching both named
volumes concurrently remains to be implemented.
`LOAD` accepts numbered BASIC source lines, validates a candidate program before
replacing the current one, and clears session variables only after success.
`SAVE` serializes the numbered program; `DIR` lists immediate entries in sorted
name order and marks directories with `/`. `CD` changes the session's default
directory. `DELETE` removes a file, and `RENAME` moves a file if its destination
does not exist. `FORMAT` recursively removes all files and subdirectories under
the selected directory, preserving the directory itself; formatting a volume
root erases its contents. These are QL/32-specific command semantics pending
compatibility references.

`ql32::runtime::MemoryService` supplies `FREE()` with a comma-delimited
snapshot: total free bytes, largest contiguous free block, and free-block count.
Fields unavailable on a platform are empty, preserving their CSV positions.
`FREE(0)`, `FREE(1)`, and `FREE(2)` return those metrics individually as
numbers. ESP32 reports currently free 8-bit-capable heap and uses ESP-IDF heap
statistics for fragmentation; Linux reports `MemAvailable` (with an
available-pages fallback) and does not provide fragmentation metrics. Values
do not represent memory owned by one BASIC session.

`ql32::ui::Service` defines asynchronous alert, confirmation, dialog, menu,
and line-input requests keyed by session and request IDs. `QueuedService`
delivers requests to a platform adapter; results are consumed once by polling,
and canceling a session removes its outstanding UI requests. BASIC exposes
`ALERT title$, message$` as a command and `CONFIRM(title$, message$)` as a
numeric function (`1` confirmed, `0` cancelled). The QL/32-specific `PAGER`
command uses line-input requests to pause generated listings. `executeResumable`
returns `Suspended` while a request waits; the host dispatches it through the
service and resumes the owning session when ready. VM state is retained per
interpreter, so other sessions can continue. Clearing or destroying an
interpreter cancels its outstanding UI requests. The synchronous `execute`
convenience reports an error if a BASIC program suspends and should not be used
by a host that needs to handle UI requests.

## M3 graphics slice

The portable graphics service owns one default pixel window per BASIC session
and channel. The `#0` and `#1` surfaces are created lazily; unqualified
graphics commands target the current default, initially `#1`. Coordinates are
integer pixels with `(0,0)` at the top-left; drawing outside the window is
clipped. Ink and paper
are indices into a session's color palette, initially the QL eight-color order
(black, blue, red, magenta, green, cyan, yellow, white). The service owns
graphics state and exposes no platform drawing types. Palette edits and
cycling are deferred. Graphics commands use these QL/32-specific forms, with
channel qualification available where shown: `INK index` / `INK #channel,index`,
`PAPER index` / `PAPER #channel,index`, `PLOT x,y` / `PLOT #channel,x,y`,
`LINE x1,y1,x2,y2` / `LINE #channel,x1,y1,x2,y2`,
`RECT x,y,width,height[,fill]` / `RECT #channel,x,y,width,height[,fill]`,
`CIRCLE x,y,radius[,fill]` / `CIRCLE #channel,x,y,radius[,fill]`,
`TEXT x,y,text$` / `TEXT #channel,x,y,text$`, `ROTATE degrees`,
`WINDOW x,y,width,height`, `WINDOW #channel,x,y,width,height`,
`CLOSEWINDOW [#channel]`, and the clear forms `CLS`, `CLS #channel`,
`CLS ink,paper`, and `CLS #channel,ink,paper`. Graphics channel selectors are
optional and use `#`; argument-taking commands put a comma between the selector
and their arguments. `WINDOW` without a channel uses the current graphics default
(initially `#1`); the channel form moves and resizes that channel's window
relative to its owning task's origin. Each task has a screen-space origin and
canvas size. The window manager translates task-relative window positions and
clips visible pixels to the task canvas and physical display. A window may
extend beyond the task canvas without losing its retained pixels. The
supervisor can move or resize the task canvas without changing the program.
Drawing coordinates remain local to the selected window. `CLOSEWINDOW`
releases the selected channel's graphics canvas;
the next graphics command creates a fresh default window for that channel.
`RECT` and `CIRCLE` draw outlines when `fill` is omitted or `0`, and solid
shapes when `fill` is `1`. `PLOT x,y` draws one pixel in the current ink color.
`TEXT` positions the top-left of the text. `CLS` clears the default graphics
channel; `CLS #channel` clears a selected channel. `CLS ink,paper` sets those
colors on the default channel and clears it; `CLS #channel,ink,paper` does the
same for a selected channel. The chosen ink and paper remain active for later
drawing, and the clear uses the selected paper color. Coordinates, dimensions,
radii, and color indices must be integers. `INK` and `PAPER` accept values in
the active window palette. The Linux, CYD, and VGA32 4-bit windows accept
indices 0..15; VGA output maps the palette to its available hardware colors.

The portable `graphics::WindowManager` canvas API accepts `PixelDepth::One`,
`PixelDepth::Four`, and `PixelDepth::Eight`; new windows default to
`PixelDepth::Four`. Pixels are packed at 1, 4, or 8 bits, and each canvas
exposes the corresponding 2, 16, or 256 index range.
Changing depth preserves the canvas while truncating stored indices to the new
depth. `WindowManager` can enforce a total canvas-byte budget. This C++ API is
connected to the Linux, CYD, and VGA32 BASIC graphics services. `WINDOW` moves
or resizes the current task's window relative to its origin. Supervisor task
control exposes each task's canvas origin and size and can change its viewport;
the window manager clips task windows to that viewport and the display. The C++
supervisor methods can also hide, raise, or tile session windows; BASIC window
arrangement commands remain unimplemented.

`WindowManager` stores managed canvases in one lazily-grown, bounded arena.
Closing or resizing a canvas compacts the live blocks, and closing the last
canvas releases the backing allocation. CYD and ESP32 VGA firmware configure a
76,800-byte canvas budget. This portable arena is shared by both targets; the
CYD runtime memory behavior still needs a hardware stress check.

The current pixel window can be queried with `GWIDTH()`, `GHEIGHT()`,
`GORIGINX()`, `GORIGINY()`, `GDEPTH()`, `GROTATION()`, and `GPALETTESIZE()`.
`GORIGINX()` and `GORIGINY()` return its top-left position in absolute screen
pixels. `GPALETTE$(index)` returns
the indexed color as an uppercase `#RRGGBB` string. `ROTATE degrees` requests
one of 0, 90, 180, or 270 degrees clockwise; it is supported by the CYD TFT
adapter and reports an unsupported-operation error on adapters without
rotatable displays. These QL/32-specific calls return live window dimensions
in pixels, bits per pixel, current orientation, and palette entry count.

`ql32::runtime::ChannelRegistry` assigns handles for opened endpoints and
dispatches to the file adapter, serial writer, or null sink. File channels
provide line reads with explicit EOF, text writes, exact-byte reads and writes,
absolute seek, individual close, and session cleanup. The Linux directory
adapter confines file paths to its configured root. Generic `OPEN` forms are:

```basic
INCLUDE "ql32.inc"
file = OPEN(KDeviceFile, "DATA.BIN", "READ")
serial = OPEN(KDeviceSerial)
sink = OPEN(KDeviceNull)
window = OPEN(KDeviceWindow)
WINDOW #window, 160, 0, 160, 180
```

`KDeviceFile`, `KDeviceSerial`, `KDeviceNull`, and `KDeviceWindow` are typed
numeric constants from `ql32.inc`. Window opens take no parameters and allocate
a graphics-capable channel; `WINDOW #channel,x,y,w,h` sets its task-relative
bounds. The
legacy `OPEN(path, mode)` file form remains supported.
The legacy zero-argument serial endpoint writes text and bytes to the platform
serial output; configured UART channels support input as specified in
[QL32-HW-001](QL32-HW-001.md). Null endpoints discard text, bytes, and graphics
output. `READ$(channel)` is a line read,
`EOF(channel)` as a non-consuming 1/0 check, `WRITE channel, text` as a
newline-terminated write, and `CLOSE channel` to release a handle. Modes are
`"READ"`, `"WRITE"` (truncate), and `"APPEND"`. At EOF, `READ$` returns an empty
string; `EOF` distinguishes that from an empty line. Handles are valid only in
the interpreter session that opened them and close when it ends. These
QL/32-specific calls are not historical channel syntax.

`WRITE` is shorthand for one newline-terminated text item. `PRINT #channel`
can produce the same line and also supports multiple expressions and
separators; a trailing `\` emits a line feed explicitly.

Line-oriented `INPUT` defaults to keyboard channel `#0`; file handles may be
selected explicitly. Prompts default to output channel `#1`. Supported forms
include `INPUT variable`, `INPUT prompt$; variable`, `INPUT #file, variable`,
`INPUT prompt$ #file, variable`, and the explicit form
`INPUT #promptChannel, "prompt", #readChannel, variable`. Keyboard input
suspends only its BASIC session; file input reads one line synchronously.
Configured serial channels support asynchronous line reads; see [QL32-HW-001](QL32-HW-001.md). Null input endpoints are not implemented.

Exact byte transfers and random access use `#channel IN count, buffer$`,
`#channel OUT count, buffer$`, and `#channel AT offset`. `AT` sets a zero-based
absolute position; `IN` requires the full byte count, and `OUT` writes the
requested prefix of the string as opaque bytes. Operations are limited to
8192 bytes. Linux directory files and ESP32 SD files support them. Append
channels cannot seek. Strings preserve arbitrary bytes for these operations,
but are not safe for text functions when they contain invalid UTF-8. This
replaces the earlier proposed `INPUT count, #channel, buffer$` and `SEEK`
spellings and avoids Toolkit II's combined `#channel\position` notation.

## Hardware channels and memory buffers

Hardware devices use the common session-owned channel namespace. `OPEN`
configures a device through a platform adapter; `IN`, `OUT`, `IOREAD`,
`IOWRITE`, and `XFER` perform the operations supported by that channel.
`ALLOC` and `DEALLOC` manage session-owned byte buffers for binary I/O. The
portable runtime validates channel and buffer ownership, while platform
adapters reserve pins and arbitrate physical buses.

The current Linux/macOS virtual adapter and ESP32 Arduino profiles implement
GPIO, ADC, SPI, I2C, UART, parallel GPIO banks, capacitive touch, and timers.
IrDA is reserved but deferred until a transceiver and protocol are selected.
Board include files provide board-specific pin and bus constants. Detailed
syntax, supported operations, initialization behavior, memory byte order, and
examples are specified in [QL32-HW-001](QL32-HW-001.md). These hardware APIs
are QL/32-specific; they do not claim SuperBASIC or OPL conformance.

## M4 managed UI foundation

The M4 graphics window manager owns retained canvases and portable window
properties. The startup reserves `#0` for the command/error console and `#1`
for user/program output with graphics. Additional channel IDs and window
backing are allocated on demand. Each window channel owns its text state and
retained canvas. `PRINT #channel,...` and graphics commands address a selected
window. The same namespace addresses file, serial, and future network
endpoints, subject to their capabilities. The supervisor may update a window's
position, viewport, visibility, or stacking order and request a tiled
arrangement. The compositor redraws
affected screen regions from the canvases so overlapping windows never destroy
covered content. Window management is independent of interpreter scheduling
and platform drawing libraries. See
[QL32-UI-001](QL32-UI-001.md#m4-window-manager-and-compositor).

The queued UI service accepts session-owned dialog schemas with ordered text,
edit, integer, float, choice, and check fields. A presenter submits typed values
as one result; it rejects wrong types and out-of-range numeric values. The Linux
console presenter handles all current field types and menu selection for host
testing. A cancelled dialog yields no field updates. Menus carry unique, nonzero command
IDs separately from labels and shortcut strings; selection returns the ID, not
the visual item position. These definitions and results use the asynchronous
request queue. BASIC declaration commands and VM resumption for dialog/menu
results are implemented through session-owned `DINIT`/`DIALOG` and
`MINIT`/`MENU` handles. `DGET$` and `DGET` retrieve submitted dialog values;
`MENU` returns the stable command ID or zero on cancellation. Linux console
presentation and a non-blocking ESP32 line presenter are implemented. The
embedded presenter accepts one line per prompt; board-specific visual dialog
layouts are not part of this line presenter.

The embedded scheduler-backed REPL and BASIC programs use `TASK` to start a
task from storage. The command form `TASK "path.bas"` reports its new task ID
to console channel `#0`; the function form
`task_id = TASK("path.bas")` returns the ID without printing. Add
`KTaskWait` to either form to wait for child completion. Wait mode focuses the
child while it runs, then resumes the caller; child status and errors can be
read with `TASKRESULT` and `ERR`/`ERR$`/`ERRX$`. The supervisor REPL also
provides `TASKS`, `TASKRESULT id`, `TASKCHANNELS id`, `LOGON id`, `LOGOFF`,
`KILL id`, `TASKVIEW id,origin-x,origin-y,width,height`,
`SLICE [instructions]`, `PRIORITY task-id,weight`, `SUSPEND id`, and
`RESUME id`. An asynchronously started task keeps its interpreter, VM
state, and channel handles alive at an interactive prompt after its startup
source completes. `TASKRESULT id` prints available properties; the function
form `TASKRESULT(id, selector)` returns status, channel count, error code or
detail, kind, priority, saved resume priority, or task canvas origin and size.
The corresponding `KTaskResultCanvasOriginX`, `KTaskResultCanvasOriginY`,
`KTaskResultCanvasWidth`, and `KTaskResultCanvasHeight` constants are in
`ql32.inc`. `TASKVIEW id,origin-x,origin-y,width,height` is a supervisor-only
command that changes the task's screen-space origin and clipping canvas; its
origin coordinates may be negative and its dimensions must be positive
integers. `GETTASK(KTaskCount)` returns retained task-record count, including
the supervisor and terminal records; `GETTASK(KTaskHandle, position)` returns
the task ID at a zero-based position ordered by ID. Both selectors are
supervisor-only, and are defined in `ql32.inc`. Window coordinates stay
relative to the task origin. `TASKCHANNELS` reports
reserved and open handles for a selected task. `LOGON` routes embedded console
input to an idle worker; its prompt shows the task ID. BASIC commands then
operate on that worker's variables, program, window, and channel table.
`LOGOFF` returns input to the supervisor. `KILL id` stops an active task or
removes a completed, failed, or cancelled task record and its saved result.
Channel handles are owner-checked by
interpreter session; each session's `#0` and `#1` refer to its own console and
graphics window, while sessions can address the same board through shared
platform adapters. Worker `#0` text and supervisor diagnostics use the shared
console stream; `#1` text and graphics go to that worker's window. The
cooperative scheduler uses smooth weighted round-robin scheduling; a UI or
keyboard wait suspends only its owner. The default instruction slice is 128
bytecode instructions.
The supervisor can change the global slice with `SLICE n` (1..65536); `SLICE`
without an argument reports the current value. A smaller slice returns control
to the scheduler sooner, while a larger slice reduces switching overhead.
Each active task has a non-negative 32-bit priority weight (default 4).
`PRIORITY id,n` changes a task's weight; larger values receive proportionally
more scheduler turns. `SUSPEND id` saves a task's current priority, sets its
priority to 0, and retains its interpreter state and channels. `RESUME id`
restores the saved priority. `PRIORITY id,n` sets the priority and its baseline
directly; setting it to 0 clears any saved resume priority, so a later `RESUME`
cannot restore the old value. Use a positive `PRIORITY` to enable it again.
There is no automatic wake-up timer. `TASKS` reports the current slice and each
task's priority, showing `SUSPENDED` when it has a saved resume priority and
`DISABLED` when its zero baseline has no saved priority. Its output defaults to
the current print channel (initially `#1`); `TASKS #channel`
overrides the destination for that listing. Every eligible task with positive
weight receives turns in proportion to its weight, while tasks
waiting for console input do not consume turns.
`KILL` stops tasks except the supervisor, and the currently attached worker
must be logged off before killing. Log off before suspending the currently
attached task, too. These commands are wired into embedded REPLs,
not the Linux command loop. Host tests verify the reference sequence, weighted
frequency, zero-priority behavior, and slice controls; CYD and VGA32 hardware
verification of priority controls is pending.

On the CYD display, the supervisor can show or hide a one-line, topmost
diagnostic bar with `DEBUGBAR ON` and `DEBUGBAR OFF`. It reports free heap,
largest free heap block, currently allocated heap blocks, active task count,
and wall-clock time. The time field shows `--:--:--` until the device clock is
synchronized. This display command is QL/32-specific.

## M5 clock service

`ql32::runtime::ClockService` provides optional Unix epoch seconds for wall
time and monotonic milliseconds for elapsed-time measurement. A target may
report wall time as unavailable until its clock is set or synchronized; elapsed
time remains available. The Linux adapter supplies host system and steady
clocks. No BASIC clock functions or setter API are defined yet.

## M6 Wi-Fi service

`ql32::runtime::NetworkService` starts Wi-Fi station association asynchronously
and reports `Disconnected`, `Connecting`, `Connected`, or `Failed`, with IPv4
and signal strength when connected. BASIC exposes the commands
`GETNET ssid$, password$` and `DISNET`, plus the functions `NETSTAT$()`,
`NETADDR$()`, and `NETSIGNAL()`. A missing adapter
reports `Unavailable`; see [QL32-NET-001](QL32-NET-001.md) for state and
credential-handling details. The first platform adapter is ESP32 Wi-Fi station
mode. HTTP, sockets, and BLE are later slices.
