# QL/32 — User Interface Contract

**Document ID:** QL32-UI-001  
**Status:** Architecture baseline; command signatures provisional

The OPL model comes from [Programming Psion Computers](../reference/README.md).
QL/32 adopts declarative controls and menus, not OPL source compatibility.

QL/32 provides two portable UI levels:

1. Managed controls — `ALERT`, `CONFIRM`, and later declarative dialogs and menus (`DINIT`, `DEDIT`, `DINT`, `DCHECK`, `DIALOG`, `MINIT`, `MCARD`, `MENU`).
2. Drawing — later graphics windows and primitives such as `LINE`, `RECT`, `CIRCLE`, `TEXT`, `INK`, `PAPER`, and `CLS`.

UI is keyboard-operable, session-owned, and automatically laid out. Dialog
edits are transactional: values update BASIC variables only after confirmation.
Modal UI blocks the owning session's interaction, not the entire system.

## Planned BASIC catalogue

| Milestone | Commands | Purpose |
| --- | --- | --- |
| M2 | `ALERT`, `CONFIRM` | Standard message and confirmation |
| M3 | `INK`, `PAPER`, `LINE`, `RECT`, `CIRCLE`, `TEXT`, `CLS` | Drawing through portable windows |
| M4 | `DINIT`, `DTEXT`, `DEDIT`, `DINT`, `DFLOAT`, `DCHOICE`, `DCHECK`, `DBUTTONS`, `DIALOG` | Declarative dialogs |
| M4 | `MINIT`, `MCARD`, `MENU` | Declarative menus with stable command IDs |
| M4+ | `MCASC`, `MPOPUP`, `DFILE` | Extended controls |

Standard controls shall have system-managed layout, focus, validation, and
keyboard navigation. Esc cancels without changing BASIC variables; confirmation
commits edited values. Menu shortcut keys are separate from command identity.
Each window, dialog, and menu belongs to a session and is released when that
session ends. A waiting UI request suspends only that session.

These APIs are implemented as registered native calls above the VM. The BASIC
parser does not need FabGL, LVGL, or a particular display size. Exact argument
signatures, return values, and error codes require a later command catalogue.
