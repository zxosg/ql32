# QL/32 — System Services Baseline

Portable system service boundaries are display, input, storage, audio, network,
GPIO, and clock. Service availability is capability-driven and selected by the
board profile. No BASIC program may require direct memory-mapped hardware access.

## Storage service (M2)

`ql32::runtime::StorageService` exposes text reads, text writes, and directory
listings using relative paths. It returns stable service error codes for
invalid paths, missing files, permission failures, I/O failures, and unavailable
services. The Linux adapter confines resolved paths to a configured root and
uses atomic replacement for writes; the CLI uses its launch directory as that
root. The ESP32 SD adapter confines paths to the mounted card root, validates
mount availability, flushes writes before returning, and sorts directory
entries. FAT-backed SD writes are not guaranteed to survive power loss
atomically.

`ql32::runtime::ChannelService` provides session-owned file handles for line
reads, text writes, exact-byte transfers, and zero-based absolute seeks in read,
truncate, or append mode. Exact transfers preserve NUL and arbitrary byte
sequences, with BASIC operations capped at 8192 bytes. Append handles cannot
seek. Handles close individually or when the owning session ends. Linux and
ESP32 SD adapters confine channel paths to their configured roots. Serial and
network channel adapters remain future work.

BASIC line `INPUT` reads keyboard input asynchronously from logical channel
`#0`, or reads a line synchronously from an explicitly selected file channel.
The keyboard request suspends only its BASIC session. Exact-byte operations use
`#channel IN count, buffer$`, `#channel OUT count, buffer$`, and
`#channel AT offset`. Serial input as a channel is not implemented.

## Platform capability descriptor (M5 foundation)

`ql32::platform::Capabilities` is populated by the selected board adapter. It
reports the profile name, optional display dimensions, pixel format,
orientation and scaling, available input kinds, and enabled system services.
The descriptor is validated before use and contains no board-library types.
Unsupported services remain absent and must fail gracefully at their API
boundary. Concrete pin maps, display timings, and hardware drivers remain
board-qualification work.

## Keyboard input contract (M5)

`ql32::input::KeyboardService` exposes a non-blocking `poll()` that returns
one optional platform-neutral key event. Events distinguish text characters,
navigation/editing keys, function keys, press/release state, and common
modifiers. The FabGL VGA32 adapter uses the PS/2 virtual-key queue and maps
printable ASCII plus common navigation keys and F1-F12; platform-specific
non-ASCII key layouts remain adapter work. The VGA32 prompt maps printable
key-down events, Backspace, and Enter into a line-oriented BASIC input path;
serial is used for BASIC output.

## Clock service (M5)

`ql32::runtime::ClockService` exposes optional Unix wall time in seconds and
monotonic elapsed milliseconds. Wall time may be absent until a board clock is
configured or synchronized; monotonic time has an unspecified origin and is
used for durations. The Linux adapter uses `system_clock` and `steady_clock`.
The ESP32 adapter uses `time()` for wall time and `esp_timer_get_time()` for
monotonic uptime. It treats timestamps before 2020-01-01 as unsynchronized; the
VGA32 image reports this state and current monotonic uptime over serial. The
interface does not choose BASIC keyword names or permit wall-clock changes.
