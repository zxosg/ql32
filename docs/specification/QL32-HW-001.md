# QL/32 Hardware Channel Specification

**Document ID:** QL32-HW-001  
**Status:** Implemented in the Linux/macOS virtual adapter and the current ESP32 Arduino profiles; IrDA and Raspberry Pi adapters are deferred.  
**Compatibility:** QL/32-specific API. No SuperBASIC or OPL compatibility claim.

## Channel and memory model

Hardware endpoints use `OPEN(deviceKind, ...)` and return ordinary session-owned
channel handles. `CLOSE` releases the handle and its resources; session exit
closes remaining channels. `OPEN` validates and configures the device once.
Scalar `IN` and `OUT` calls do not reinitialize pins. Physical pins and I2C
addresses are reserved while open. Board C++ code, Arduino types, and bus
libraries remain inside platform adapters.

`ALLOC(byteCount)` returns the base address of a zero-filled byte allocation
owned by the BASIC session. The supported address range is checked on every
access. `DEALLOC address` releases an allocation; session cleanup releases
allocations left open. `PEEK(address)` and `POKE address, byte...` access
bytes. `PEEK_W`/`POKE_W` and `PEEK_L`/`POKE_L` access native-endian 16- and
32-bit values. Device I/O always moves bytes unchanged.

```basic
buffer = ALLOC(4)
POKE buffer, 17, 34, 51, 68
value = PEEK_W(buffer)
POKE_L buffer, 305419896
DEALLOC buffer
```

`IN(channel)` reads scalar devices; `IN(channel, register)` reads a device
register. `OUT channel, value` writes scalar devices, and
`OUT channel, register, value` writes a register. `IOREAD` and `IOWRITE` use
allocated buffers: stream form is `(channel, address)` and register form is
`(channel, register, address)`. `IOREAD` returns byte count or a negative QL/32
error code; `IOWRITE` returns zero on success or a negative error code.
`XFER #channel, txAddress, txLength, rxAddress, rxLength` performs one raw
transaction. Zero lengths omit that phase. `IN$` is not part of this API.

## Device opens and operations

All numeric pin and bus values may be written directly or supplied through a
board include. Common constants are in `ql32.inc`; supported board aliases are
in `boards/<board>/ql32-hardware.inc` and are copied into `data/boards/` for
embedded storage.

| Device | `OPEN` parameters | Operations and behavior |
| --- | --- | --- |
| GPIO | `pin, KPinInput|KPinOutput[, pull[, KPinInitialValue, value]]` | `IN` reads 0/1 on input; `OUT` writes 0/1 on output. Pull is `KPullNone`, `KPullUp`, or `KPullDown`. Output latch is preloaded before enabling output. `CLOSE` returns the pin to input. |
| ADC | `pin[, resolution]` | `IN` returns raw counts. ESP32 supports 9–12-bit resolution; `KAdcResolution12` selects 12 bits. No voltage conversion is promised. |
| SPI | `bus, chipSelectPin, clockHz, mode[, bitOrder]` | `XFER` is the raw transaction API. Mode is 0–3; bit order is 0 for MSB-first or 1 for LSB-first. Chip select stays active across both phases and is released on completion. |
| I2C | `bus, address[, clockHz]` | `IN`/`OUT` access one-byte registers. Register-buffer `IOREAD`/`IOWRITE` start at the selected one-byte register. `XFER` performs a raw transaction and uses a repeated start when a receive phase follows a transmit phase. Addresses are 7-bit. |
| Serial | `port, baud[, frame[, flow]]` | Configured UART channels support newline-terminated `WRITE`, line `READ$`, and stream-buffer `IOREAD`/`IOWRITE`. The initial ESP32 adapter supports 8N1 and no flow control; UART 0 remains reserved for the REPL. |
| Parallel | `bit7Pin, bit6Pin, ..., bit0Pin, KPinMode, mode[, KPinInitialValue, byte]` | Eight distinct GPIOs form one unsigned byte. `IN` reads and `OUT` writes in the selected direction. `KPinInputOutput` starts as input; `OUT channel, KPinMode, KPinOutput|KPinInput` changes direction explicitly. The output latch is set before output is enabled. |
| Capacitive touch | `pad` | `IN` returns calibrated/debounced 1 for touched and 0 otherwise. Thresholds and raw counts remain adapter-specific. |
| Timer | `periodMilliseconds, KTimerOneShot|KTimerPeriodic` | Nonblocking `IN` returns accumulated expirations. Timers use monotonic time and do not promise hard real-time precision. |
| IrDA | — | The device-kind constant is reserved. Opens report unavailable until a transceiver and protocol are selected. |

For configured UART `READ$`, an incomplete line waits without blocking the
scheduler. It suspends only the calling session and resumes when a complete
CR, LF, or CRLF-terminated line arrives; the terminator is removed. The Linux
virtual adapter supports deterministic line injection in tests and loopback
for the desktop CLI. The legacy zero-argument `OPEN(KDeviceSerial)` remains
the existing output-only serial channel.

The ESP32 adapters reserve board-owned display/storage pins and pins claimed by
open channels. I2C endpoints on the same bus must use one clock rate and cannot
open the same device address twice. SPI transactions use the board-mapped
shared `SPIClass` instances, so existing display/storage users and BASIC
channels share the same peripheral rather than creating a competing bus.
Opening a device unsupported by a target reports unavailable. The host virtual
adapter models all listed devices except IrDA; host GPIO and ADC values can be
set deterministically by tests.

## Acceptance coverage

`ql32_hardware_tests` covers memory bounds and endian round trips, GPIO/ADC
values, parallel bit order and direction changes, I2C scalar and buffer
register access, SPI transfers, serial text/binary I/O and line waiting,
capacitive touch, timer expiry, resource ownership, and invalid syntax.
`ql32_hardware_repl` drives the host REPL with scripted BASIC input and the
virtual adapter. Linux/macOS builds and the supported ESP32 PlatformIO profiles
are the automated build gates. Physical electrical behavior still requires
board-level testing.
