# QL/32 — System Requirements & Architecture Specification

**Document ID:** QL32-SRS-001  
**Version:** 1.1
**Status:** Consolidated design baseline  
**Date:** 5 November 2026

## Vision

QL/32 is a compact, standalone BASIC computer combining an SMSQ/E-inspired
structured BASIC, Psion-inspired application interfaces, and native ESP32
services. It boots into an immediate programming environment and supports
graphics, storage, UI, networking, and hardware capabilities.

It shall not emulate Motorola 68000 hardware or execute QL ROMs, QDOS, or
SMSQ/E binaries.

## Architectural commitments

1. The BASIC grammar, compiler, VM, scheduler, and public APIs are portable.
2. Each interpreter runs in an independent session with owned resources.
3. Display, input, storage, audio, network, GPIO, and clock services are accessed only through platform-neutral interfaces.
4. The window manager and UI toolkit have no FabGL- or LVGL-specific public types; window canvases retain their contents independently and the compositor restores covered regions after overlapping windows move or close.
5. Firmware selects drivers through a board profile at build time.
6. Hardware-dependent APIs expose capabilities and fail gracefully when absent.

The current tree builds all four maintained ESP32 environments on macOS:
`lilygo_vga32`, `olimex_esp32_sbc_fabgl`, `esp32_2432s028`, and
`esp32_2432s028_spiffs`. This verifies firmware compilation only. It does not
replace native Linux CI or physical board acceptance.

On 2026-11-05, the Olimex firmware was rebuilt and flashed. Printable ASCII
font output, paged HELP input/resumption, and the 80x56 Mandelbrot demo were
checked on its VGA display. The Mandelbrot example uses the existing graphics
surface because `WINDOW` resize caused `bad_alloc` on the board. Runtime,
scheduler, graphics, and graphics UI tests were compiled and run directly with
`g++`; all four passed. CMake was unavailable, so this was not a full CTest run.

## Current open work, ordered by readiness

1. **CYD regression:** Visually verify the latest `PLOT` attractor program in
   window `#1` at `0,0,320,192`; record that points animate, stay within the
   window, and do not corrupt the console. If the current board image predates
   commit `de88fe5`, rebuild/flash the CYD SPIFFS profile before checking.
2. **Memory evidence:** Repeat launch/kill cycles on CYD with `FREE()`,
   `FREE(1)`, and `FREE(2)` before/after workers and graphics tasks. Separate
   task source-buffer release from retained task-result records and the canvas
   arena's high-water capacity. The recorded 3-worker + Mandelbrot combination
   exceeds compile-time memory; determine the supported concurrency envelope
   and keep that limit explicit.
3. **Task API acceptance:** On CYD, verify `TASK` command/function forms with
   and without `KTaskWait`, child focus/logoff behavior, and error code/detail
   propagation after child failure. Verify that `PRIORITY id,0` clears the
   suspend restore value, distinct from `SUSPEND`/`RESUME`.
4. **Native Linux validation:** Run the Linux preset and all CTest cases on
   an actual Linux host or CI runner. The `build/linux` directory in this
   macOS checkout is also compiled with Darwin and is not Linux evidence. Add
   a dedicated Olimex profile test for its GPIO/FFS configuration; it currently
   has no profile-specific CTest case.
5. **VGA acceptance:** On Olimex and/or LILYGO, verify physical PS/2 key input
   and global shortcuts, startup/SD behavior, line UI, clock, supervisor,
   task/window behavior, and Wi-Fi. Olimex VGA capture, printable ASCII, paged
   HELP, and Mandelbrot output were verified on 2026-11-05. Keep
   LILYGO-specific physical acceptance separate.
6. **Performance characterization:** Measure attractor frame time and actual
   ESP32 frequency for SINGLE/DOUBLE at supported CPU settings before deciding
   whether numeric math or display transfer is the bottleneck.
7. **Feature backlog:** Define a portable bounded bitmap-font format and
   graphics-channel font selection (`FONT`, `LOAD FONT`); implement REPL
   `EDIT linenumber`; then consider palette editing/cycling, task window
   management/tiling, string splitting/slicing, indirect calls, and network
   channels. BLE and new board families stay deferred until separately scoped.

The known operational failure is resource exhaustion when too many large
workers are compiled concurrently; heap-retention readings remain inconclusive
rather than proving a leak.

## Acceptance principles

Linux is the first conformance host. Every supported platform shall pass the
shared interpreter, scheduler, UI, and filesystem conformance suite applicable
to its enabled capabilities.
