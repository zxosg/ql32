# QL/32 — VM and Runtime Contract

**Document ID:** QL32-VM-001  
**Status:** Portable session state and cooperative round-robin scheduler implemented; Linux windows retained and composited; embedded board composition pending

The VM executes portable bytecode. A session contains its own instruction
state, variables, channels, error state, and owned native resources. Native
services communicate through a registry and must not expose platform-library
objects to bytecode or language code.

Asynchronous operations preserve synchronous BASIC syntax. For example, a
dialog call puts only its owning session into `WAITING_UI`; other sessions
continue to be scheduled. Results are delivered through generation-safe handles
so stale events cannot target a terminated session.

`ql32::vm::SessionScheduler` owns one `Interpreter` per task. Each `tick()`
advances one task by a configured maximum number of bytecode instructions, then
returns control to the host. Tasks move among `Runnable`, `WaitingUi`,
`Completed`, `Failed`, and `Cancelled`. A waiting task retains its VM state and
does not stop another task from running. The host dispatches UI requests between
ticks and calls `tick()` again after resolving them. Each task writes to its
provided output stream, which must outlive the task. Source compilation occurs
when the task first runs and is not included in the instruction budget.

The scheduler is cooperative and single-threaded; it does not create OS threads.
The Linux graphics service now retains and composites session canvases. CYD
and VGA32 still need compositor-backed presenters before multiple scheduled
sessions can share an embedded display concurrently.
