# QL/32 — VM and Runtime Contract

**Document ID:** QL32-VM-001  
**Status (2026-11-04):** Portable session state and cooperative smooth weighted round-robin scheduler implemented. The current macOS build passes all 57 CTest cases, including scheduler, priority, slice, async UI, and debugger behavior. CYD hardware acceptance covers weighted rates, adjustable slices, suspend/resume, cancellation, and multi-session output. The `TASK` wait/error-return forms and direct `PRIORITY id,0` reset behavior remain targeted hardware checks. Linux needs a native host run; VGA hardware acceptance is deferred while the board is unavailable.

The VM executes portable bytecode. A session contains its own instruction
state, variables, channels, error state, and owned native resources. Native
services communicate through a registry and must not expose platform-library
objects to bytecode or language code.

Asynchronous operations preserve synchronous BASIC syntax. For example, a
dialog call puts only its owning session into `WAITING_UI`; other sessions
continue to be scheduled. Results are delivered through generation-safe handles
so stale events cannot target a terminated session.

`ql32::vm::SessionScheduler` owns one `Interpreter` per task. Each `tick()`
advances one task by a configured maximum number of bytecode instructions, then
returns control to the host. Tasks move among `Runnable`, `WaitingUi`,
`WaitingTime`, `Completed`, `Failed`, and `Cancelled`. A waiting task retains its VM state and
does not stop another task from running. The host dispatches UI requests between
ticks and calls `tick()` again after resolving them. Each task writes to its
provided output stream, which must outlive the task. Source compilation occurs
when the task first runs and is not included in the instruction budget.

The scheduler is cooperative and single-threaded; it does not create OS threads.
Among tasks that can make progress, smooth weighted round-robin scheduling
selects each task according to its priority weight. Default weight is 4;
supervisor controls accept non-negative 32-bit weights. Setting a task's
weight to zero suspends it without cancelling it; its interpreter state and
channels remain allocated, but it is never selected. A positive weight resumes
it from its retained state. The supervisor can change the global
instruction budget with `SLICE n` (1..65536, default 128), trading faster
switching for more scheduling overhead. Tasks waiting for input are omitted
until input is submitted; tasks waiting for a UI result are polled and remain
eligible.
`PAUSE delay` stores a monotonic wake deadline for the calling session. Timed
waiters are omitted from scheduling until that deadline, without sleeping the
host loop or another session.

Linux, CYD, and VGA32 graphics services retain and composite session canvases.
Both ESP32 event loops drive the scheduler-backed REPL and service input and UI
replies between ticks. Host tests verify the reference sequence, weighted
frequency, zero-priority suspension and priority restoration, slice control,
and UI suspension. CYD supervisor flow, weighted rates, slice control, and
suspend/resume behavior have been checked on hardware. VGA32 display and input
verification remain pending until hardware is available.
